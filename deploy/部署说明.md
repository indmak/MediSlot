# MediSlot 云端部署说明（宝塔面板）

## 服务器信息

| 项 | 值 |
|----|----|
| 域名 | `medi.goposy.com` |
| 站点目录 | `/www/wwwroot/medi.goposy.com` |
| 面板 | 宝塔面板（仅用于域名绑定 / 文件管理 / SSL / 反向代理） |
| 运行方式 | 网站程序在 Docker 中运行，应用 + 数据库各一个容器 |
| 应用对外端口 | 宝塔 Nginx 反代 → `127.0.0.1:8080`（不直接暴露 8080） |
| 数据库端口 | 不映射到宿主机，仅容器网络内可访问 |

## 架构

```
                ┌────────────────── 宝塔面板 ──────────────────┐
 用户 ── 443 ──▶│ Nginx(站点 medi.goposy.com)  反向代理 + SSL  │
 (HTTPS)        └───────────────┬──────────────────────────────┘
                                │ http://127.0.0.1:8080
                     ┌──────────▼──────────┐        ┌──────────────────┐
                     │  medislot-app        │──3306─▶│  medislot-db     │
                     │  (Spring Boot 容器)  │ 内网   │  (MySQL 8.4 容器)│
                     └─────────────────────┘        └────────┬─────────┘
                                                              │
                                                    ./data/mysql (持久化)
```

## 一、首次部署

### 1. 上传代码

把整个仓库放到 `/www/wwwroot/medi.goposy.com`（宝塔文件管理器上传或 `git clone`）。

### 2. 准备环境变量

```bash
cd /www/wwwroot/medi.goposy.com
cp .env.prod.example .env.prod
vi .env.prod          # 修改 DB_ROOT_PASSWORD / DB_PASSWORD，务必改成强密码
```

### 3. 构建并启动

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build

# 查看启动日志（等待出现 "Started MediSlotApplication"）
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f app
```

> 首次构建会在容器内用 Maven 打包（已配置阿里云镜像加速），约 3–8 分钟。
> MySQL 首次启动会执行 `scripts/init.sql` 创建 `medislot_db`。

### 4. 配置宝塔站点

1. **域名绑定**：网站 → 添加站点，域名 `medi.goposy.com`，PHP 版本选「纯静态」。
2. **反向代理**：站点设置 → 反向代理 → 目标 URL `http://127.0.0.1:8080`，
   或直接采用 `deploy/nginx-medi.goposy.com.conf` 的配置。
3. **SSL**：站点设置 → SSL → Let's Encrypt 申请证书，开启「强制 HTTPS」。

完成后访问 `https://medi.goposy.com` 即可。

> 生产环境默认不写演示数据（`medislot.seed.enabled=false`）。
> 如需在云端写入演示数据，在 `.env.prod` 里加 `MEDISLOT_SEED_ENABLED=true` 后重启应用即可
> （仅在库为空时写入一次；生产环境建议保持关闭，改用管理后台/数据库维护）。

## 二、更新代码后重新部署

```bash
cd /www/wwwroot/medi.goposy.com
git pull                                   # 或重新上传
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build app
```

## 三、停止 / 清理

```bash
# 停止（保留数据）
docker compose --env-file .env.prod -f docker-compose.prod.yml down

# 停止并删除数据（慎用，会清空 MySQL）
docker compose --env-file .env.prod -f docker-compose.prod.yml down -v
rm -rf ./data/mysql
```

## 四、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 构建时拉取 Docker 镜像超时 | 服务器访问 Docker Hub 不稳定 | 面板 → Docker → 配置 → 添加镜像加速（阿里云/腾讯云），或为 daemon 配代理 |
| Maven 依赖下载慢 | 未走国内镜像 | 已内置 `apps/backend/docker/maven-settings.xml`（阿里云）；如仍慢可换成公司私服 |
| 应用启动报 Connection refused | MySQL 未就绪 | 依赖 `depends_on: condition: service_healthy` 已处理；不要删健康检查 |
| 8080 已被占用 | 宿主机有别的服务 | 改 `.env.prod` 的 `APP_PORT`，同步改 Nginx 反代地址 |
| 打不开、502 | 应用没起来 | `docker compose ... logs -f app` 看日志；确认 `127.0.0.1:8080` 可访问 |
| 数据重启后丢失 | 用了 `down -v` | `down` 不删数据，`down -v` 才删，谨慎使用 |
| 密码泄露 | `.env.prod` 被提交 | `.gitignore` 已忽略，确认未提交；泄露则改密码 |
